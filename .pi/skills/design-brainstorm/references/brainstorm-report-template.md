# Шаблон отчёта брейншторма

Копируй структуру, а не текст. Пустых блоков не оставляй: либо содержательно,
либо `N/A — <причина>`. Утверждение без `путь:строка` — гипотеза, и так и
помечено. Числовых индексов соответствия принципам в отчёте нет.

```markdown
# Брейншторм: <объект> (<ветка>@<sha>, <дата>)

## Цель и рамки
- Вопрос: <что решаем, одной фразой>
- Объект: <вся библиотека / юнит / публичный API / фича / дифф>
- Нельзя ломать: <публичный API, форматы вывода, FPC+Delphi, без зависимостей>
- Сколько вариантов готовы рассмотреть: <N>

## Факты
- Прочитано: <файлы и что именно искал>
- Не проверено: <сборка/тесты/рантайм — причина>
- `git status`: <чисто / что незакоммичено>
- Fan-in сводка (из `scripts/design-facts.sh`):
  | Тип | Внешних упоминаний | Вывод |
  |---|---|---|
  | `T...` | 0 | живёт сам для себя |

## Карта ответственностей
| Кто | Что знает | Что создаёт | Чем владеет | От чего зависит |
|---|---|---|---|---|
| `TLog` | уровень + текст | — | — | `TLogLvl` |

## Линзы
| Линза | Наблюдение | Метка |
|---|---|---|
| SRP | <факт + путь:строка> | `TENSION` |
| OCP | <...> | `HOLDS` |
| LSP | <...> | `CHEAP` |
| ISP | — | `N/A — у базового типа один метод` |
| DIP | <...> | `DEBT` |
| GRASP: Creator | <...> | `HOLDS` |
| GRASP: Expert | <...> | `HOLDS` |
| GRASP: Low Coupling | <...> | `TENSION` |
| GRASP: Polymorphism | — | `N/A — ветвление отсутствует` |
| KISS | <...> | `CHEAP` |
| YAGNI | <...> | `DOGMA` |

Метки: `HOLDS` · `TENSION` · `CHEAP` · `DEBT` · `DOGMA` · `N/A` · `DOC`.

## Коллизии (главное)
1. **<S ↔ K>** — `путь:строка`
   - Полюс A: <что требует один принцип>
   - Полюс B: <что требует другой>
   - Основание выбора: <боль сегодня / цена / обратимость>
   - Что теряем: <прямо, без смягчений>

## Идеи
| # | Идея | Покупает (боль) | Цена | Обратимо | Риск |
|---|---|---|---|---|---|
| 1 | Ничего не делать | — | 0 | да | боль остаётся |
| 2 | Удалить `<тип>` | <fan-in 0> | <1 файл, N строк> | да | <доки> |
| 3 | <шов> | <...> | <...> | нет | <...> |

## Отобрано (≤3)
1. **<идея>** — почему: <критерий 1,2,3>. Первый шаг: <1-3 строки/тест>.
2. ...

## Припарковано
| Идея | Триггер пересмотра |
|---|---|
| <абстракция> | <событие: «когда появится 3-й логгер»> |

## Отброшено
- <идея> — причина: <нет потребителя / ломает API / цена > выгоды>.

## Решение
<Один абзац: что делаем и что этим покупаем. Если решение — «не делать»,
сказать это прямо и записать, что считаем приемлемым.>

## Открытые вопросы
1. <вопрос, на который нужен ответ человека, а не догадка>

## Сознательно не делаем
- <что не делаем и почему — чтобы через месяц не начать заново>
```

## Проверка перед сдачей

- [ ] Все утверждения о коде имеют `путь:строка`; гипотезы помечены.
- [ ] В отчёте есть хотя бы одна `TENSION` или явное «коллизий нет, потому что…».
- [ ] `do nothing` присутствует среди идей.
- [ ] Ни одна отобранная идея не держится только на «правильности принципа».
- [ ] Для каждого `DEBT` записан триггер, а не «потом».
- [ ] Нет новых зависимостей и предложений сломать публичный API без цены.
- [ ] Нет числового рейтинга соответствия принципам.
