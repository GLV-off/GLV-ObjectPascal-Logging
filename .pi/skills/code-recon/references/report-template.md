# Шаблон отчёта о ревью

Копируй структуру, а не текст. Пустых блоков не оставляй: либо содержательно,
либо `N/A — <причина>`. Оценки без `путь:строка` в отчёт не попадают.

```markdown
# Ревью: <что именно> (<ветка>@<sha-короткий>, <дата>)

## Окружение и границы
- Проверено: <оси/файлы, которые реально прочитаны>
- Не проверено: сборка — <причина>; тесты — <причина>; рантайм — <причина>
- Незакоммиченные изменения: <есть/нет, что затрагивают>

## Карта
- Назначение: <1-2 строки>
- Публичный API: <фасад/точки входа>
- Слои: <типы → база → реализации → фасад>, нарушений: <N или нет>
- Тесты: <что покрыто>, флаки: <где>
- Доки: <какие обещания даются>

## Находки

### BLOCKER
1. `<путь>:<строка>` — <что не так>
   Цитата:
   ```<lang>
   <≤3 строки>
   ```
   Последствия: <что сломается и при каких условиях>
   Минимальная правка: <1-3 строки, без рефакторинга>

### BUG
...

### RISK
1. `<путь>:<строка>` — <что не так>
   Условия срабатывания: <нагрузка / гонка / другой компилятор / большой вход>
   ...

### SMELL
... (кратко, по строке на находку)

### DOC
| Документ | Обещает | Код на самом деле |
|---|---|---|
| `<файл>:<строка>` | ... | `<путь>:<строка>` — ... |

## Прочее
- <список без разбора деталей, с путями>

## Рекомендуемый порядок работ
1. <что закрыть первым и почему>
2. <какие находки объединяются в одно изменение + какой тест его закрывает>
3. <что трогать не нужно / что осознанно оставлено>
```

## Проверка отчёта перед выдачей

- [ ] Каждая находка имеет `путь:строка` и цитату; «гипотезы» помечены.
- [ ] Нет утверждений о сборке/тестах, которые не запускались.
- [ ] Объявленные в правилах проекта долги не выданы за новые находки —
      они либо подтверждены, либо дополнены новыми условиями.
- [ ] Severity не завышена ради драматизма и не занижена ради «зелёного» вида.
- [ ] Находки, ломающие публичный API, отмечены как дорогие.
- [ ] Список находок не раздут: топ-15 в основном блоке, остальное — «прочее».
- [ ] Рекомендации выполнимы в текущей структуре проекта, без новых зависимостей.
