# Бэклог из находок ревью
Этот скилл **не ищет** дефекты и не правит код. Он берёт готовый отчёт
`code-recon` (или журнал S1–S4), проверяет доказательства и превращает их в
строки `doc/backlog_ru.md` с ID, статусом и критерием приёмки.
## Жёсткие правила
1. **Сначала `code-recon`.** Нет отчёта/находок — нет бэклога. Не выдавайте
   «улучшить модуль» за находку.
2. **Каждый пункт — `путь:строка` + последствие.** Файл и строка должны
   существовать сейчас; устаревшую строку обновите или пометьте `[stale]`.
3. **Один пункт = одно осмысленное изменение + один тест.** Два контракта —
   два пункта с зависимостью, а не «починить всё».
4. **По умолчанию dry-run.** `findings-to-backlog.sh` ничего не пишет без
   `--write`; перед записью покажите строки и diff.
5. **Дедупликация по `путь:строка`.** Существующий пункт не получает новый ID;
   вывод — `dup` со старым ID. ID `BL-xxx` не переиспользуются.
6. **Статусы честные.** `done` — только тест (падал до/проходит после) или
   явное решение; `wontfix` — только с причиной. Иначе `new`.
7. **Приоритет.** В `next` 3–5 пунктов; не больше одного с `API: breaking`.
   Остальное — `later`, новые строки — в `inbox`.
8. **Код не трогать.** Любая правка `lib/`, `test/`, `demos/` — отдельная
   задача с отдельным тестом; здесь только `doc/backlog_ru.md`.
9. **Никаких `jq`/`xmllint`/сети.** Только `bash`, `awk`, `sed`, `grep`,
   `git`; скрипт пишет только во временный каталог, а с `--write` — в бэклог.
10. **Формат.** `doc/**` — CRLF, `.pi/skills/**` — LF; русский язык, пути и
    команды — как есть.

## Фаза 1 — собрать вход

Источники по убыванию доверия:

1. Свежий отчёт `code-recon` (`report-template.md`), с блоками
   `### BLOCKER/BUG/RISK/SMELL/DOC`.
2. Журнал S1–S4 в `doc/skills_plan_ru.md`: прогоны, дрифты, падения.
3. «Известные дефекты» в `AGENTS.md` — только подтверждённые цитатой.

Проверьте доказательства глазами:

```bash
sed -n '130,150p' lib/src/GlvLogFiles.pas   # пример: строка async-бага
git ls-files | wc -l                        # числа из доков
bash .pi/skills/pascal-package-sync/scripts/pkg-inventory.sh .
```

Что уже закрыто, не открывайте заново. На S5 F8 (3 юнита вне пакетов) закрыт:
`pkg-inventory.sh` даёт `covered=17|uncovered=0`; в бэклоге он отмечен как
проверенный, а не как открытый пункт.

## Фаза 2 — преобразовать

Сухой прогон (ничего не пишет):

```bash
bash .pi/skills/backlog-from-review/scripts/findings-to-backlog.sh report.md
```

Скрипт понимает:

- заголовок `### BUG` (или `## BUG`) и нумерованный/маркированный пункт
  ``1. `путь:строка` — текст``;
- метку в строке `[BUG] ...`, `BUG: ...`;
- таблицу `### DOC` с `| \`путь:строка\` | ... |`.

Выход:

```text
| BL-017 | BUG | `test/src/TestEnv.pas:1` | a new finding | new |
| BL-001 | BUG | `lib/src/GlvLogFiles.pas:138` | ... | dup |
RESULT|new=1|dup=1
SUMMARY|findings=2|new=1|dup=1
```

`new` — можно добавлять, `dup` — уже есть (ID из бэклога). Если находок нет:
`RESULT|new=0|dup=0`, exit `2`. Ошибки: `64` — аргументы, `66` — нет
отчёта/бэклога, `3` — `--write` без маркера.

## Фаза 3 — разложить и приоритизировать

1. Перенесите `new`-строки из `inbox` в `next`/`later` и заполните поля по
   `references/item-template.md`.
2. Проверьте: `Последствие` — поведение, `Минимальная правка` — без новых
   зависимостей, `Тест/критерий` — конкретная команда/тест.
3. `next` — 3–5 пунктов; `API: breaking` — максимум один. Остальное — `later`.
4. Зависимости: `BL-003`/`BL-004`/`BL-006` (BOM/усечение) можно закрывать
   вместе, но это разные пункты; `BL-002` зависит от `BL-001`.
5. Не добавляйте `done`/`wontfix` без теста/причины.

## Фаза 4 — записать

После просмотра строк и решения о приоритете:

```bash
cp doc/backlog_ru.md /tmp/backlog.before.md
bash .pi/skills/backlog-from-review/scripts/findings-to-backlog.sh --write report.md
git diff -- doc/backlog_ru.md
```

`--write` вставляет **только новые** строки перед маркером
`<!-- findings-to-backlog:append -->`, дубликаты не пишет. Если маркера нет —
exit `3`, файл не меняется. Для теста можно указать копию:
`--backlog /tmp/backlog.md`, чтобы не трогать рабочий бэклог.

## Фаза 5 — проверить DoD

1. **Тест дедупликации:** фрагмент из двух находок, одна уже в бэклоге →
   `RESULT|new=1|dup=1`.
2. **Объём:** `grep -c '^| BL-' doc/backlog_ru.md` — ≥ 8 (в seed 16).
3. **Доказательства:** у каждой строки есть `` `путь:строка` ``.
4. **Статусы:** только `new/in-progress/done/wontfix`; `wontfix` с причиной.
5. **Приоритет:** в `## next` 3–5 строк; `API: breaking` не больше одного.
6. **Нет дублей:** одинаковый `путь:строка` не встречается дважды.
7. **Нет правок кода:** `git status --porcelain` не содержит `lib/src`,
   `test/src`, `demos/simple/src` (кроме уже существующих чужих изменений).
8. **Скрипты:** `bash -n`, `--help` exit 0, неизвестный аргумент exit 64.

## 10 проверок (готовые команды)

1. **Сухой прогон:** `printf '%s\n' '### BUG' '1. `lib/src/GlvLogFiles.pas:138` — dup' '2. `test/src/TestEnv.pas:1` — new' > /tmp/findings.md && bash .pi/skills/backlog-from-review/scripts/findings-to-backlog.sh /tmp/findings.md` — `RESULT|new=1|dup=1`.
2. **Запись в копию:** `cp doc/backlog_ru.md /tmp/backlog.md && bash .pi/skills/backlog-from-review/scripts/findings-to-backlog.sh --write --backlog /tmp/backlog.md /tmp/findings.md` — `WROTE`, оригинал не изменён.
3. **Объём:** `grep -c '^| BL-' doc/backlog_ru.md` — `16`.
4. **Доказательства:** `grep '^| BL-' doc/backlog_ru.md | grep -v '`[^`]*:[0-9]'` — пусто.
5. **Статусы:** `grep '^| BL-' doc/backlog_ru.md | grep -Ev '\| (new|in-progress|done|wontfix) \|$'` — пусто.
6. **Дубли:** `grep -o '`[^`]*:[0-9]*`' doc/backlog_ru.md | sort | uniq -d` — пусто.
7. **Приоритет:** `awk '/^## next/{f=1;next}/^## later/{f=0}f && /^\| BL-/{n++}END{print n}' doc/backlog_ru.md` — `5`; `awk '/^## next/{f=1;next}/^## later/{f=0}f' doc/backlog_ru.md | grep -c 'API: breaking'` — `0`.
8. **Синтаксис:** `bash -n .pi/skills/backlog-from-review/scripts/findings-to-backlog.sh` — без ошибок.
9. **Аргументы:** `bash .pi/skills/backlog-from-review/scripts/findings-to-backlog.sh` — exit `64`; `--help` — exit `0`.
10. **Чистота:** `git status --porcelain` — только бэклог/скилл/план, без артефактов сборки.

## Не дублировать

- `code-recon` — найти, доказать и оценить severity; здесь только перенос
  уже найденного.
- `design-brainstorm` — выбрать архитектуру; здесь не обсуждаем варианты.
- `pascal-build-probe` (S1) — запуск сборки; здесь только ссылка на результат.
- `pascal-package-sync` (S2) — правка `.lpk`/`.lpi`; здесь фиксируем долг.
- `test-cross` (S3) — запуск тестов; здесь тест указан как критерий.
- `doc-sync-ru` (S4) — сверка доков; здесь DOC-находки становятся пунктами.
- Исправление кода — вообще не эта сессия.

## Если окружение недоступно

Нет `git` — дедупликация по бэклогу всё равно работает, но проверка
`git status` пропускается (`SKIP|git|absent`). Нет отчёта/бэклога — exit `66`,
не выдумывайте ID. Нет тестового фрагмента — не утверждайте, что
`RESULT|new=1|dup=1` проверен. `--write` без маркера — exit `3`, файл не
меняется.
