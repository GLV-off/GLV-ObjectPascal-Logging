# Сверка документации с кодом (RU)

Документ — заявка, код и тесты — факт. Скилл отвечает на вопрос
«что именно в доках устарело и что с этим делать», а не «как подогнать код
под текст». По умолчанию правится **текст**; код — только отдельным явным
решением.

## Жёсткие правила

1. **Сначала прочитать, потом сверять.** `AGENTS.md`, `README.md`,
   `CONTRIBUTING.md`, `doc/map` из `references/doc-map.md` — целиком, не по
   диагонали.
2. **Нет прогона — нет «актуально».** Перед утверждением «доки синхронны»
   запустить `scripts/doc-facts.sh`; exit `2` означает дрифт.
3. **Дрифт — находка `DOC`.** Формат совместим с `code-recon`:
   `путь:строка`, цитата, фактическое значение/файл. Догадка — `[гипотеза]`.
4. **По умолчанию правится дока, а не код.** «Привести код в соответствие
   с докой» — отдельное решение пользователя, с тестом и проверкой.
5. **Контракт меняется в порядке: тесты → код → доки.** Формат строки,
   имя юнита, пакет — сначала фиксируются тестом/пакетом, потом текст.
6. **Все доки в одном изменении.** Если код/API изменился, `AGENTS.md`,
   `README.md`, `doc/v1/*`, `doc/v2/*` обновляются тем же коммитом.
7. **Числа и пути — из git/ФС.** Не помнить «39 файлов» и «8 модулей»:
   `git ls-files`, `find`, `ls`; кэш памяти здесь уже подводил.
8. **Артефакты не Findings.** `out/`, `backup/`, `*.lps`, `*.ppu`, `*.exe`,
   `*.log`, автоген-`.pas` рядом с пакетами — не доки и не код для правки.
9. **Планы — не обещания.** `doc/units.md` и `doc/v2/*` могут описывать
   будущее; отсутствие будущего юнита — не дрифт, если это заявлено планом.
10. **Формат файлов.** `doc/**` — CRLF (как в репо), `.pi/skills/**` — LF;
    язык доков — русский, команды/имена — как есть.
11. **Никаких `jq`/`xmllint`/сети.** Только `bash`, `git`, `grep`, `sed`,
    `awk`, `find`.

## Шаг 1 — карта и прогон

Прочитайте `references/doc-map.md`: там таблица «документ → утверждения →
что проверяется машинно → что только руками». Затем:

```bash
cd C:/dev/glv/pas_Log
bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh .
echo "exit=$?"
```

Скрипт ничего не пишет. Он вызывает `pascal-build-probe/scripts/probe.sh`,
если тот есть, и печатает:

```text
DOC|<файл>:<строка>|<тип>|<утверждение>|<факт>
SUMMARY|checks=10|drifts=N
```

Коды: `0` — дрифтов нет, `2` — есть, `64` — неверный корень/аргументы.
`SKIP|tracked|git-absent` и `SKIP|compiler|probe-absent` — проверка не
выполнена, это не «ноль дрифтов».

## Шаг 2 — разобрать каждую строку

| Тип | Смысл | Что делать по умолчанию |
|---|---|---|
| `count` | число файлов/строк в доке не совпало с git/ФС | обновить число и объяснить, что считается |
| `ignore` | док обещает паттерн в `.gitignore` | обновить текст; менять `.gitignore` — отдельное решение |
| `path` | упомянутый файл не существует | исправить ссылку/перенести файл; путь из `doc/v1` — частая причина |
| `unit` | имя юнита из плана отсутствует в `lib/src` | обновить план или реализовать юнит отдельно |
| `format` | формат строки из AGENTS не найден в коде | сверить с тестом; если код намеренно другой — править AGENTS |
| `contract` | `AsStr`/уровни/сигнатуры расходятся с реализацией | источник истины — тест; менять контракт только с тестом |
| `test-requires` | список пакетов `.lpi` в доке неполный | обновить AGENTS по фактическим `RequiredPackages` |
| `env` | утверждение про компилятор/`PATH` | сверить с `probe.sh`; не выдавать «нет компилятора» за факт |

Текущий снимок S4 (2026-10-28): на первом прогоне было 10 проверок и 11 дрифтов; после параллельной правки путей в AGENTS/README повторный прогон даёт 6: `39` против фактического `git ls-files`, `*.o`, `AsyncFileEngine`, `AsStr` UNKNOWN, `Test.lpi` requires и FPC вне `PATH`. Число не константа — перепроверяйте `doc-facts.sh`, не пересказывайте старый снимок.

## Шаг 3 — решение по каждому дрифту

Для каждой строки выберите ровно один вариант и запишите его:

- **`DOC-TEXT`** — правится только текст (ошибка в доке, код/тест правы).
- **`CODE`** — правится код (док/тест описывают желаемое поведение);
  только по явному запросу, с тестом и последующей проверкой сборки.
- **`DEFER`** — решение отложено; находка уходит в бэклог S5 с триггером.

Не смешивайте: если меняется формат вывода, сначала обновите ожидания в
`LogTestInt.pas`, затем код, затем `README.md`/`AGENTS.md`. Обратный порядок
даёт «зелёную» доку при красном тесте.

## Шаг 4 — правка (только после решения)

1. Минимальный diff: одна находка — одно изменение, без переписывания
   соседних разделов.
2. Не трогать `lib/pkg/*/*.pas` (автоген), `backup/`, `out/`, `*.lps`.
3. Сохранить CRLF в `doc/**`; проверить `file`/`perl` после правки.
4. Если изменился публичный API/формат — обновить **все** места:
   `AGENTS.md` (контракты), `README.md` (примеры/таблица), `doc/v1`/`doc/v2`.
5. Повторный прогон:

```bash
bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh .
git diff --check
```

Остаточные `DOC`-строки — не «почти всё», а незакрытые находки.

## Шаг 5 — отчёт

Укажите: какие документы читали, команду и exit-код, число проверок/дрифтов,
какие строки остались, что правили (текст или код) и почему. Если правили
код — команду сборки/тестов и её результат; если не запускали — «не
проверено». Нельзя писать «доки синхронны», пока exit `2`.

## 10 проверок (готовые команды)

1. **Полный прогон:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh .` — exit 2 и `SUMMARY|checks=10|drifts=6` на текущем коде.
2. **Количество:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep '^DOC|AGENTS.md:67|count'` — `39 tracked files` против фактического `git ls-files`.
3. **Юнит:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep '^DOC|doc/units.md:11|unit'` — `GLV.Log.AsyncFileEngine` отсутствует.
4. **Test.lpi:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep '^DOC|AGENTS.md:61|test-requires'` — в доке только `glv_log_contract`, фактически ещё `glv_log_def_engine`.
5. **Окружение:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep '^DOC|AGENTS.md:53|env'` — `probe: fpc=2 outside PATH`.
6. **AsStr:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep '^DOC|AGENTS.md:99|contract'` — `UNKNOWN` только в комментарии.
7. **Согласованность счётчика:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep -c '^DOC|'` равно `drifts` из `SUMMARY`.
8. **Нет ложных артефактов:** `bash .pi/skills/doc-sync-ru/scripts/doc-facts.sh . | grep '|path|' | grep -E '(^|/)(out|backup)/|\.lps$'` — пусто.
9. **Синтаксис:** `bash -n .pi/skills/doc-sync-ru/scripts/doc-facts.sh` — без ошибок.
10. **Чистота диффа:** `git status --porcelain` — только доки/скилл/план, без `out/`, `*.exe`, `*.ppu`, `*.lps`.

## Не дублировать

- `code-recon` — инвентаризация и классификация находок; здесь только
  текстовые утверждения и `DOC`-строки.
- `design-brainstorm` — выбор архитектуры; здесь не обсуждаем варианты.
- `pascal-build-probe` (S1) — детект компилятора; здесь вызываем `probe.sh`,
  не дублируем его проверки.
- `pascal-package-sync` (S2) — правка `.lpk`/`.lpi`; здесь только читаем
  `RequiredPackages`.
- `test-cross` (S3) — запуск тестов; здесь тесты — источник фактов.
- `backlog-from-review` (S5) — хранение отложенных `DOC`-находок.

## Если окружение недоступно

Сообщите: «доки не сверялись полностью»; перечислите, что проверяли, и
какие строки получены (`SKIP|tracked|git-absent`, `SKIP|compiler|probe-absent`,
`ERROR|root|...`). Не выдавайте `SKIP` за ноль дрифтов и не выдумывайте
фактическое число файлов.
