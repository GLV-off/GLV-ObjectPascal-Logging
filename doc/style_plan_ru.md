# План: стайлгайд GLV Log для агентов

Статус: S0 выполнен (каталог правил), S1–S5 не начаты.
Область записи: `doc/style/**`, `.pi/skills/pascal-style/**`, `scripts/` этого скилла,
секция «Стиль» в `AGENTS.md`. Код `lib/`, `test/`, `demos/` в этих сессиях **не правится** —
стилевые нарушения существующего кода живут в `doc/backlog_ru.md`.

Вход: `doc/style/00_rules_catalog_ru.md` (77 правил-предложений с фактами и проверками).
Отношение к существующим скиллам: `pascal-style` не дублирует `code-recon` (находки),
`pascal-package-sync` (пакеты), `test-cross` (харнесс), `doc-sync-ru` (доки).

## Архитектура (принято)

| Слой | Где | Роль |
|---|---|---|
| Инварианты + маршрутизация по областям | `AGENTS.md` (авто-загрузка) | 7 строк правил + таблица «glob → модули» |
| Канон правил | `doc/style/NN_*_ru.md` | что правильно; нормативные формулировки, примеры `путь:строка` |
| Процедура применения | `.pi/skills/pascal-style/SKILL.md` | как выбрать модули, как реагировать на HARD/SOFT/METRIC |
| Машинная проверка | `scripts/style-check.sh` | `STYLE|файл:строка|уровень|правило|деталь` + `SUMMARY` |

Вложенные `AGENTS.md` в подкаталогах не используются: pi загружает контекст-файлы
только из рабочего каталога и его предков (`configuration.md`), вниз — нет.

## DoD всего плана

- Правило без проверки или без уровня — не существует (SOFT-исключение допустимо).
- HARD/manual ≤ 16; всё остальное HARD проверяется `style-check.sh` или `rg`.
- Baseline метрик зафиксирован числами: рутин 66, `>24 SLOC` = 2, `>3 параметров` = 0,
  максимум строк в юните = 287 (`GlvLogFiles.pas`).
- Ни один пункт `09_legacy_exceptions_ru.md` не превращается в находку ревью.
- `git status --porcelain` после сессии — только файлы стиля (плюс чужие правки,
  если они были до начала сессии).
